Traitement de 1 428 dalles LiDAR IGN HD

Le Parc possédait environ 280 Go de nuages de points qu'aucun agent ne pouvait ouvrir dans QGIS. J'ai écrit la chaîne qui les transforme en modèles de terrain, de surface et d'élévation, plus un hillshade multi-directionnel, assemblés en mosaïque. Une interface web dans Docker permet aux agents de la relancer seuls.

  • Huit cœurs en parallèle : de 62 s à 9 s par dalle, soit ×6,9. Environ 3,6 h estimées pour les 1 428 dalles.
  • Validation sur 12 dalles : 15 à 25 cm d'écart entre mon MNT et la BD ALTI 5 m de l'IGN.
  • Triangulation (TIN) pour le MNT, interpolation IDW sous forêt dense, où le TIN produit des pics.
  • Marge de recouvrement de 50 pixels et padding des bords pour supprimer les lignes aux jointures.

Python, PDAL, laspy, rasterio, rvt-py, GDAL, Streamlit, Docker

Code hébergé par le Parc. Démonstration sur demande.

Assistant qui répond sur la charte du Parc

Les chargés de mission fouillaient à la main des dizaines de PDF pour retrouver une règle ou un engagement. L'assistant répond en langage naturel à partir de 380 documents et affiche les passages sources sous chaque réponse.

  • API FastAPI avec trois routes : question, ajout de PDF, état du service.
  • Embeddings sentence-transformers, index FAISS et ChromaDB.
  • Sélection des passages par MMR, pour éviter qu'ils se répètent.
  • Génération par un modèle de langage local, sans service cloud.
  • Testé à la main par l'équipe. Les tests automatisés sont ce que j'écrirais en premier la prochaine fois.

Python, FastAPI, sentence-transformers, FAISS, ChromaDB, Ollama

Code hébergé par le Parc. Démonstration sur demande.

Migration d'une base de données et d'un serveur cartographique en production

Les deux briques arrivaient en fin de support. J'ai migré la base centrale et le serveur cartographique vers des versions maintenues, sans casser les outils qui en dépendent.

  • Coupure de service de moins d'une heure, planifiée un soir.
  • Durcissement de l'authentification de la base, application par application.
  • Deux fonctions PL/pgSQL : l'une ajoute le suivi de modification à n'importe quelle table, l'autre renseigne le code INSEE par intersection spatiale. Un seul appel suffit pour chacune.
  • Procédure de migration documentée pour la prochaine fois.

PostgreSQL, PostGIS, PL/pgSQL, GeoServer

Travail en production au Parc. Procédure et scripts décrits dans mon rapport de stage.
